## Issue #42: mpv IPC Socket ENOENT on Fedora

### Problem Analysis

The reporter on Fedora Linux sees:

```
[DEBUG] [PlayerService] IPC socket error
error: connect ENOENT /tmp/mpvsocket-331218-3
```

The mpv process is spawned but the IPC socket file is never created. The user confirmed mpv works manually with `--input-ipc-server`.

**Root Cause Hypothesis:** mpv may be crashing immediately after spawn due to:

1. Invalid/unrecognized arguments on Fedora's mpv build
2. Missing dependencies (PipeWire/Wayland quirks)
3. SELinux restrictions on socket creation in `/tmp`
4. The `--idle=yes` flag behavior differs on some mpv versions

**Current Behavior:**

- mpv is spawned with `detached: true`, `stdio: ['ignore', 'pipe', 'pipe']`
- Initial IPC delay: 200ms on Linux
- Retries: 20 attempts × 200ms = ~4 seconds total
- If mpv exits before IPC connects, error is logged but may not surface clearly

**Fix Strategy:** Improve diagnostics and error handling:

1. Add explicit mpv process exit detection with stderr capture
2. Log the exact mpv command being spawned for debugging
3. Add a pre-flight check that validates mpv can create a socket
4. Surface mpv exit errors to the user more clearly

## Issue #18: OAuth "Client ID is missing" Error

### Problem Analysis

The `ymc login` command fails with:

```
[AuthService] Sign-in failed: {"error":"Client ID is missing."}
```

**Root Cause:** In `auth.service.ts:257` and `LoginView.tsx:69`, the code calls `innertube.session.oauth.getDeviceAndUserCode()` directly without first calling `oauth.init()` or `oauth.getClientID()`.

The `youtubei.js` library's `OAuth2` class:

- `init()` (line 33-34): calls `getClientID()` before `getDeviceAndUserCode()` ✅
- `getDeviceAndUserCode()` (line 157-158): throws if `client_id` is undefined ❌

**Fix:** Call `await innertube.session.oauth.init()` before `getDeviceAndUserCode()`, which handles the full Client ID fetch + device code flow.

### Task 2: Fix OAuth2 Device Flow in AuthService

**Files:**

- Modify: `source/services/auth/auth.service.ts:220-277` (signIn method)

**Interfaces:**

- Consumes: `Innertube.create()` returns Innertube instance
- Produces: `signIn()` returns `{success, verificationUrl?, userCode?, error?}`

- [ ] **Step 1: Add oauth.init() call before getDeviceAndUserCode()**

In `auth.service.ts`, line 257, replace:

```typescript
const deviceCode = await innertube.session.oauth.getDeviceAndUserCode();
```

With:

```typescript

```
